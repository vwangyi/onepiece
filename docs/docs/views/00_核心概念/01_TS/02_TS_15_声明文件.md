## 声明文件

- 以 .d.ts结尾的文件就是ts声明文件

- 声明文件有什么用？ 
- 对js代码提供类型声明 

- 声明文件的书写位置
  - 1. 先找 放到 tsconfig.json配置的include字段的文件夹内部 
  - 2. 再找 放到 node_modules/@types文件夹中 
  - 3. 手动配置 compilerOptions.typeRoots: ["./node_modules/@types","./src/types"] 配置typeRoots 一二条就失效 
  - 4. 和js代码所在目录相同 并且文件名也相同的文件。比如 /xxx.js  /xxx.d.ts 



## 编写声明文件


- 自动生成
1. 工程是ts开发，编译之后 发布的是js文件，需要配置 declaretion： true 编译后会生成声明文件 发布即可
2. sourceMap: true  生成map映射文件

- 手动编写
1. 对已有库之前是js写的，全部改为ts版本成本很高，可以先手动编写声明文件 后续再重构为ts版本。比如vue 就是这样
2. 一些第三方库作者用js写的 并且没有提供声明文件 只有我们自己为库写声明文件 


__全局声明__

```ts
// global.d.ts
declare var console: {
  log(msg?: any): void
}
```
```js
console.log('afa')
```

__模块声明__
```ts
// loadsh.d.ts

// 声明模块
declare module "lodash" {
  export function chunk<T>(array: T[], size: number): T[][];
}
```

```ts
import _ from 'lodash'; // lodash是js写的 但我们写了声明模块就可以正常使用了
_.chunk([1,2,3,4], 2)


// 一般都不用自己写 社区都写好了  pnpm i -D @types/lodash 
```

__三斜线指令__
- 在一个声明文件中 包含另一个声明文件, 类似引入其他声明文件
```ts
/// <reference path="../../index.d.ts" />
```


## 发布声明文件
1. 当前工程使用ts开发，经过配置后 编译结果就存在 声明文件 直接发布即可
2. 为其他第三方库开发的声明文件 比如 我们为lodash写了声明文件， 发布到@types/xxx 为社区做贡献
