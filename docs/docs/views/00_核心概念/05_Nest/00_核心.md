## 三层架构
三层架构是指把整个应用程序分为三层：表示层controller、业务逻辑层service、数据访问层DAO层。 

## controller层 表示层
主要是做 对《拿到的数据》进行过滤校验 对《给出去的数据》进行处理 

## service层 业务层
对业务的增删改查的业务逻辑等等

## dao层数据访问层
对数据库的增删改查 一般用TypeORM 或 sql 

## 实体entity

## MVC
MVC只是用于三层架构中的表示层controller里面的设计模式
三层架构是整个工程的架构模式
MVC和三层架构不是同一个东西，有一定的相似性。
model view controller 指后端的controller
 三层架构的表现层采用MVC设计模式。
 M：Model，业务模型，处理业务
 V：View，视图，界面展示
 C：Controller，控制器，处理请求，调用模型和视图

## 动态模块
动态模块就是通过 类的regidter静态方法 返回一个配置对象。
imports: [......, AuthModule.register({})]


这里的 register 方法其实并不是固定的，但 nest 约定了 3 种方法名： 我们约定它们分别用来做不同的事情：
- register：用一次模块传一次配置，比如这次调用是 `AuthModule.register({auth:’admin‘})`，
  下一次可以AuthModule.register({auth:’guest‘})` 
- forRoot：配置一次模块用多次，通常用于注册根模块，例如配置根模块的全局服务或者中间件等等
- forFeature：用了 forRoot 固定了整体模块，用于局部的时候，可能需要再传一些配置，
  比如用 forRoot 指定了一些基础配置信息，再用 forFeature 指定某个模块访问的具体信息。
  具体我们后面使用`typeorm`库的时候，大家一看就明白了。


## AOP面向切面编程
AOP面向切面编程是把散落在业务代码里的公共逻辑抽出来，统一“横着切一刀”插入到方法执行前后。
- AOP是面向切面编程 就是 不改变原有代码的基础上 在程序特定位置“横向切一刀”添加行为。

比如Middleware（中间件）、Guard（守卫）、Interceptor（拦截器）、Pipe（管道）和Filter（过滤器）。
OOP是面向对象编程‌是纵向的，关注业务模块划分。但有些业务是横向的，所以需要AOP。
