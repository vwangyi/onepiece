

## 
- 第一层 controller层 视图层 表示层：  
    对《拿到的数据》进行过滤校验 对《给出去的数据》进行处理 ，
    前后端分离后这个层做的事可以给前端做，这层做的事少了 但仍然存在这一层
    这一层做的事也比较固定 有MVC架构来做这一层 view contoller model 简称MVC
    view contoller model ： 从这一层角度来说 model是指service DAO层统称model view就是前端视图 controller就是控制路由跳转
    和前端差不多  有 vue的MVVM react的MVC 等架构

    java的springMVC这个库也是专门做这一层的

- 第二层 service层 业务逻辑层：
    对业务的增删改查的业务逻辑等等

- 第三层 DAO层 数据访问层（数据访问对象）：
    对数据库的增删改查 
    数据访问层一般来说 比较固定 都是对数据库CURD 所以用 TypeORM 等库做了
    对象关系映射ORM  用后端面向对象语言来操作数据库 而不是用sql语言操作数据库 
    对于复杂sql还是需要sql语言来处理。

## 项目过大有 实体层和数据传输层
- 实体层：位于三层架构之外的一层 不属于三层中任何一层 而是在三层之间的数据传递作为实体来传递的 
    每张数据库表 对应 一个实体类
- 数据传输层（DTO数据传输对象）：这一层是 表示 数据传输对象和数据库对象并不一致，比如 男女 对应 0和1 

- 和数据库对应的 是 实体层
- 只是用来传递并不是和数据库对应 是 DTO 数据传输层

- VO BO DTO 分别是 视图对象 业务对象 数据传输对象


- 三层架构的好处是 分离关注点 三层每层只做自己的事 可维护性好

- 三层架构 的 表示层和数据访问层 都有对应库做处理 但业务层每个公司都不一样 
- 尽管都有最基本的CRUD也没人做这个事 因为每个公司都不一样，但可以针对某一个公司的业务进行封装
- 但我们作为公司的开发人员 我们在这个公司熟悉业务之后 我们可以针对公司的业务进行合理的封装 
- 我们学习其他的封装思想就可以用在这里 



 

## MVC
- model view controller  在后端单指三层架构的视图层 在前端就是整个前端架构 因为前端就是从后端分出来的

- model 模型。 在前端就是store 在后端就是services层和DAO层
- 封装《数据(属性)》和《业务逻辑(操作数据的方法)》 

- 视图 view  在前端就是vue的template react的jsx  
- 负责渲染数据

- controller
- 在前端就是 vue的vm script  
- 在前端 负责 store和template的协调作用 （调用store 处理用户输入）
- 在后端 负责调用services层 处理前端传给后端的数据
