## 容器组件展示组件相分离

hooks用来复用有状态逻辑或拆分模块的 hooks的返回值是响应式数据 不建议把ref到hooks外部做全局通信。 应用场景 比如 需要接收props的值 做不同的数据处理 就可以用hooks 依然保持响应式

store 是做全局状态管理 和全局通信的
utils是复用无状态逻辑或拆分模块的 utils返回值不是响应式数据



- 页面就是最大的容器组件



展示组件 只负责 接受 props 和 emit  不直接调用api或 store 

容器组件 负责 调store或api 并调用展示组件传给展示组件








在 Vue 中聊“高阶组件”（HOC），确实不像 React 那么频繁，因为 Vue 有更原生的混入（Mixin）和组合式函数（Composables）。但 Vue 完全支持 HOC 模式，且它是“Props 传函数”最合理的用武之地。

举一个经典场景：权限拦截高阶组件（withAuth）。

---

场景：多个页面组件需要在渲染前检查用户是否登录，未登录则跳转。

1. 定义高阶组件（容器）
它接收一个展示组件，返回一个新组件。在这个层级的逻辑中，我们只能用 props 传函数，因为此时是在 render 函数（或 setup 返回值）里进行逻辑组合，没有模板（Template），自然无法使用 @事件 语法。

```javascript

// withAuth.js - 高阶组件
import { computed } from 'vue'

export function withAuth(WrappedComponent) {
  return {
    name: 'WithAuth',
    props: {
      // 透传原组件需要的 props
      ...WrappedComponent.props 
    },
    setup(props, { slots, attrs }) {
      const isLoggedIn = computed(() => !!localStorage.getItem('token'))

      // 关键点：定义修改数据的逻辑，通过 props 传下去
      const handleForceUpdate = (newData) => {
        // 这里可以修改容器内的数据，或触发 store action
        console.log('容器接收到的数据：', newData)
        // 实际项目中可能触发 Vuex/Pinia mutation
      }

      return () => {
        if (!isLoggedIn.value) {
          return h('div', '请先登录')
        }
        // 将函数作为 prop 传递给展示组件
        return h(WrappedComponent, {
          ...props,
          ...attrs,
          // 通过 props 传递回调函数
          onUpdate: handleForceUpdate 
        }, slots)
      }
    }
  }
}
```

2. 普通展示组件使用
它通过 props 接收 onUpdate 并调用，不涉及任何 $emit。

```vue
<!-- UserProfile.vue 展示组件 -->
<template>
  <div @click="handleClick">修改姓名</div>
</template>

<script>
export default {
  props: ['userName', 'onUpdate'], // 接收函数 prop
  methods: {
    handleClick() {
      // 调用容器传下来的函数
      this.onUpdate('新名字')
    }
  }
}
</script>
```

3. 最终使用

```vue
<template>
  <WithAuth :userName="name" />
</template>
<script>
import { withAuth } from './withAuth'
import UserProfile from './UserProfile'
const WithAuth = withAuth(UserProfile);
</script>
```

---

为什么在这个 HOC 例子里，必须用 Props 传函数？

· 语法限制：@事件 是模板编译器的语法糖，底层依赖 v-on 指令。但在 render函数 / h() 中，你面对的是纯 JavaScript 虚拟 DOM 节点，没有编译器帮你绑定事件，只能通过 props 传递回调函数来实现逻辑回调。
· 动态性：HOC 是在运行时动态包裹组件，模板是静态的，无法在运行中动态声明 @事件 的监听目标。

总结区别落地：

· 有 Template（常规父子组件）→ 用 @事件（更符合 Vue 规范，调试友好）。
· 无 Template（渲染函数、高阶组件、JSX）→ 用 Props 传函数（JS 原生调用方式，是 HOC 组合逻辑的唯一解）。
