```ts
class User {
  readonly id: number // 一旦初始化后就不修改 类似const
  name: string // 应该先定义再赋值  而不是 不定义 直接赋值 
  gender: '男' | '女' = '男'
  pid: string = ''

  private publishNumber: number = 3; // 每天可以发布多少篇文章
  private currentNumber: number = 0; // 当前可以发布的文章数量

  // protected 

  // 成员修饰符 readonly public private protected 

  constructor(name: string, public age: number, private _age1: number, gender: '男' | '女' = '男') {
    this.id = Math.random();
    this.name = name;
    // 如果参数值传进来直接赋值给属性 有一种语法糖写法 像age一样 直接在参数列表里的参数加 成员修饰符 就等同于name 
    // 一定有修饰符可加 默认是 public 只要加了修饰符 就是语法糖 readonly public private protected 都行
    this.gender = gender;
  }

  publish(title: string) {
    if (this.currentNumber < this.publishNumber) {
      console.log('发布' + title);
      this.currentNumber++;
    } else {
      console.log('已达上限')
    }
  }

  // 访问器属性
  // 当给age1赋值会调用 setter 函数  小技巧 如果不写setter 就不能赋值 间接实现只读
  // 当访问age1时 会调用getter函数
  // 注意 this._age1 不能写成 this.age1  因为 对this.age1赋值 等同于 调用setter 会递归导致栈溢出
  set age1(value: number) {
    if (value < 0) {
      this._age1 = 0
    } else if (value > 200) {
      this._age1 = 200
    } else {
      this._age1 = value
    }
  }
  get age1() {
    return Math.floor(this._age1);
  }



}

const u = new User('a', 1);
u.gender = '女';

u.publish('文章1')

u.age1 = -100

console.log('age1', u.age1)

```

## 单根性
- 单根性： 一个类最多只有一个父亲
- 传递性：A是B的父类 B是C的父类 那么可以认为A也是C的父类
- 抽象类：这个类只能被继承 不能被实例化 abstract class Hell {}
- 抽象成员：子类必须要实现父类的抽象成员，只有抽象类才有抽象成员。抽象成员用abstract表示（成员有属性和方法，也就是说 有抽象属性和抽象方法）

- 静态成员： 类上面的成员是静态成员,通过类调用。 实例对象上的成员是实例成员，通过实例对象调用。 用 static 表示 （静态成员有属性和方法）


- this: 实例方法是通过实例调用 那么this是实例对象  静态方法的this是当前类。

## 为什么要讲面向对象

1. 
JS语言没有类型检查，如果使用面向对象的方式开发，会产生大量的接口，而大量的接口会导致调用复杂度剧增，这种复杂度必须通过严格的类
型检查来避免错误，尽管可以使用注释或文档或记忆力，但是它们没有强约束力。
由于js语言的弱类型解释性 天生让js做不了复杂的程序

2. TS为前端面向对象开发带来了契机
TS带来了完整的类型系统，因此开发复杂程序时，无论接口数量有多少，都可以获得完整的类型检查，并且这种检查是据有强约束力的。
ts让前端开发工程师的腰杆硬起来了
一个稍微复杂的系统 上百个类 很正常


3. 面向对象中有很多成熟的模式，可以处理复杂问题，使用面向对象可以直接用。
不是说只有面向对象思维才可以做复杂东西，而是面向对象很成熟了 所以才用面向对象。
而前端用面向对象没有走通 所以目前是 推荐hooks写法 不管是vue还是react都推荐hooks写法

## 单例模式
- 单例模式：系统中 有且只有一个实例就是单例模式。

```ts
class Board {
  private constractor() { } // 加了private 禁止使用new调用
  private static _board?: Board;
  static createBoard(): Board {
    if (!this._board) {
      this._board = new Board();
    }
    return this._board;
  }
}
const a = Board.createBoard();
const b = Board.createBoard();
console.log(a === b) // true
```
```ts
class Board {
  private constractor() { } // 加了private 禁止使用new调用
  static readonly singleBoard: Board = new Board()
}
const a = Board.singleBoard;
const b = Board.singleBoard;
console.log(a === b) // true
```
