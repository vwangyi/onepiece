## 装饰器
- 面向对象中的概念 比如 java中的注解


## 解决的问题
- 装饰器 可以 关注点分离的问题 

- 什么是关注点分离？

- 1. 在定义一个表单时， 电话 账号 密码 都有校验规则，在定义时最清楚对应的校验规则 而不是写完后再写一个校验函数 如果写完表单 在回头校验每个字段 相当于把一件事拆开了

- 2. 单独写一个校验函数 也会存在重复代码问题

- 上面2个问题的根源是 定义某些字段 能够附加的信息有限
- 装饰器作用是 为字段 类 参数 方法 提供完整的元数据信息
- 元数据就是描述数据的数据




## 装饰器本质
- 在js中 装饰器是一个函数，（那就是说 js支持装饰器的 是需要参与运行的）
- 装饰器可以修饰： 类、成员（属性+方法）、参数 

## 
```ts
class User {
  logined: string; // 描述是'账号' 校验规则：必填 必须3-5个字符
  age: number; // 必须是0-100之间的数字
}

// 上面的注释就是 字段的校验规则 但没有体现到和字段一起。 装饰器就可以实现
```

## 装饰器的返回值
- void 表示没有返回值
- 返回一个新的类，表示把装饰的类替换为新类。


## 类装饰器
- 类装饰器本质是一个函数 该函数接收一个参数 表示类本身（构造函数本身）
- @得到一个函数

- 多个普通函数的执行顺序是 从上到下。多个装睡器执行顺序是 从下到上
```ts

// 类定义后 立马调用
function test(target: new (...args: any[]) => object) {
  console.log('target', target)
}

function test1(str: string) {
  return function (target: new (...args: any[]) => object) {
    console.log('target', target)
  }
}

@test
@test1('sadf')
class A {

}

```

## 成员装饰器
- 属性装饰器 和 方法装饰器

- 属性装饰器本质也是一个函数，装饰器函数接收2个参数
1. 如果是静态属性 是类本身，若是实例属性则为类的prototype 
2. 属性名 字符串

- 方法装饰器本质也是一个函数，装饰器函数接收3个参数
1. 如果是静态属性 是类本身，若是实例属性则为类的prototype 
2. 属性名 字符串
3. 属性描述对象
```ts
function d(target: any, key: string, descriptor: PropertyDescriptor) {
}
class A {
  @d
  prop1: string
  @d
  static prop2: string
}
```
